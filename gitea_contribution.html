統計規則、限制與部署說明

以各 repo 預設分支的第一 parent 歷史為範圍，包含直接提交。日期依 Committer date 篩選，顯示台灣時間。PR 的合併 SHA 核對成功後，優先以 merged_by 歸屬登入使用者；否則使用登入帳號的 email 與 committer email 比對。無 email 時只納入可驗證的 PR 合併者紀錄並提示資料受限。

一般 merge 比較第一 parent；squash 計最終一筆；rebase 逐筆計主線提交。不重複加總開發分支的原始 commits。不掃完整 PR 清單或讀取 PR patch；message 缺少 PR 線索時可能無法取得 issue 關聯。只解析 PR body 的 Organization/Repository#number。

變更量＝新增＋刪除；缺失資料顯示「—」，不補零。合併結果代表整個變更，不是單一原作者的工作量。同 repo 同 SHA 去重，跨 repo 可能重複。資料只留在記憶體，可手動匯出 CSV。

單次請求逾時預設 180 秒，可調整為 30–1800 秒。可隨時停止並保留已取得紀錄。舊版 Gitea 以原始 commit diff 補讀統計；若收到登入頁，請先在同一瀏覽器登入 Gitea。HTTP 帳密傳輸沒有 TLS 加密，適用於指定受控內網。

部署：將 gitea_contribution.html 放到 Apache 網站根目錄下的部署子目錄，並沿用該目錄的網站路徑。若 Apache 尚未設定無副檔名路徑，可在該目錄的 .htaccess 加入以下規則（需 mod_rewrite 與 AllowOverride FileInfo）；Traefik 應將該部署子目錄對應的 URL 路徑路由至 Apache，保留路徑：

RewriteEngine On
RewriteRule ^gitea_contribution$ gitea_contribution.html [L]

若 .html 可開、無副檔名 URL 不可開，請檢查 rewrite。若收到 HTML 而非 JSON，請檢查 /gitea/api/v1 的 Traefik 路由。若站台 CSP 禁止 inline script/style，需由管理員為此單檔配置適當 hash 或 nonce。
